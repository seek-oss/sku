# Spec Delta

## ADDED Requirements

### Requirement: SSR CSP is configured through one `csp` option

SSR apps MUST configure CSP through a `csp` option with two peer policies, `enforced` and `reportOnly`.
Each policy MUST accept `true` or an object with optional `extraSources` and `reportTo`.
`true` MUST enable the policy with sku's default directives and no `report-to` directive.
A policy that is omitted MUST be disabled.
Neither policy MUST inherit values from the other.

#### Scenario: Enforced policy only

- **WHEN** an SSR app sets `csp: { enforced: true }`
- **THEN** the response includes a `Content-Security-Policy` header without a `report-to` directive
- **AND** the response does not include a `Content-Security-Policy-Report-Only` header

#### Scenario: Report-Only policy only

- **WHEN** an SSR app sets `csp: { reportOnly: true }`
- **THEN** the response includes a `Content-Security-Policy-Report-Only` header
- **AND** the response does not include a `Content-Security-Policy` header

#### Scenario: Policies do not inherit

- **WHEN** an SSR app sets `csp: { enforced: { extraSources: { 'connect-src': ['https://browser-intake-datadoghq.com'] } }, reportOnly: true }`
- **THEN** the `Content-Security-Policy-Report-Only` header does not contain `https://browser-intake-datadoghq.com`

### Requirement: SSR CSP directives are extensible per directive

For SSR apps, sku MUST append each policy's `extraSources` to the matching directive of that policy.
A supported directive that sku does not emit by default MUST be emitted as `'self'` followed by the configured sources.
Sku MUST keep its own sources for every directive, including `script-src` nonces and hashes, and MUST NOT add duplicates.

#### Scenario: Extra connect-src host

- **WHEN** an SSR app sets `csp: { enforced: { extraSources: { 'connect-src': ['https://browser-intake-datadoghq.com'] } } }`
- **THEN** the production `Content-Security-Policy` header contains `connect-src 'self' https://browser-intake-datadoghq.com`
- **AND** in development the directive still includes `ws: wss:`

#### Scenario: Extra script-src host

- **WHEN** an SSR app sets `extraSources: { 'script-src': ['https://cdn.example.com'] }` on a policy
- **THEN** that policy's `script-src` directive includes `https://cdn.example.com` alongside sku's `'self'`, hashes and any requested nonce

#### Scenario: Directive not emitted by default

- **WHEN** an SSR app sets `extraSources: { 'frame-src': ['https://www.youtube.com'] }` on a policy
- **THEN** that policy contains `frame-src 'self' https://www.youtube.com`

#### Scenario: Each policy uses its own extras

- **WHEN** an SSR app sets different `extraSources` on `enforced` and `reportOnly`
- **THEN** each header contains only its own policy's extra sources

#### Scenario: No extra sources leave the policy unchanged

- **WHEN** an SSR app sets `csp: { enforced: true }`
- **THEN** the `Content-Security-Policy` header is identical to the one generated by `cspEnabled: true` before this change

### Requirement: SSR report-to is a URL

Each policy's `reportTo` MUST be an absolute `http:` or `https:` URL.
Sku MUST name the enforced policy's endpoint `csp` and the Report-Only policy's endpoint `csp-report-only`.
Sku MUST add `report-to <name>` to each policy that sets `reportTo`, and MUST emit a `Reporting-Endpoints` header with an entry for each of those policies.

#### Scenario: Enforced report-to

- **WHEN** an SSR app sets `csp: { enforced: { reportTo: 'https://csp.example.com/report' } }`
- **THEN** the `Content-Security-Policy` header contains `report-to csp`
- **AND** the response includes `Reporting-Endpoints: csp="https://csp.example.com/report"`

#### Scenario: Both policies report

- **WHEN** both policies set `reportTo: 'https://csp.example.com/report'`
- **THEN** the response includes `Reporting-Endpoints: csp="https://csp.example.com/report", csp-report-only="https://csp.example.com/report"`

#### Scenario: Endpoint name instead of a URL

- **WHEN** an SSR app sets `reportTo: 'csp'` on a policy
- **THEN** sku reports a config validation error

### Requirement: Invalid extra sources are rejected

The supported directives are `script-src`, `style-src`, `img-src`, `font-src`, `connect-src`, `frame-src`, `media-src`, `worker-src`, `manifest-src` and `form-action`.

Sku MUST fail config validation when a policy's `extraSources` contains an unsupported directive name, a quoted source (such as `'unsafe-inline'`, a nonce or a hash), a bare `*`, or a scheme-only source (such as `https:`) under `script-src`.

#### Scenario: Unsupported directive

- **WHEN** a policy sets `extraSources: { 'default-src': ['https://example.com'] }`
- **THEN** sku reports a config validation error

#### Scenario: Keyword source

- **WHEN** a policy sets `extraSources: { 'style-src': ["'unsafe-eval'"] }`
- **THEN** sku reports a config validation error

#### Scenario: Scheme in script-src

- **WHEN** a policy sets `extraSources: { 'script-src': ['https:'] }`
- **THEN** sku reports a config validation error

#### Scenario: Scheme outside script-src

- **WHEN** a policy sets `extraSources: { 'worker-src': ['blob:'] }`
- **THEN** config validation passes

### Requirement: CSP options match the build type

Sku MUST fail config validation when an SSR app sets any of `cspEnabled`, `cspExtraScriptSrcHosts`, `cspReportOnlyEnabled`, `cspReportOnlyExtraScriptSrcHosts`, `cspReportTo`, `cspReportOnlyReportTo` or `cspDelivery`, or when a static Vite or webpack app sets `csp`.
Each error MUST name the option to use instead.

#### Scenario: SSR app sets a flat CSP option

- **WHEN** an SSR app sets `cspExtraScriptSrcHosts`
- **THEN** sku reports a config validation error that points to `csp.enforced.extraSources['script-src']`

#### Scenario: Static app sets csp

- **WHEN** a static Vite app sets `csp`
- **THEN** sku reports a config validation error that points to the flat `csp*` options

## MODIFIED Requirements

### Requirement: SSR CSP assumes relative publicPath only

SSR CSP MUST assume a relative `publicPath` so Document assets are covered by `'self'`.

Absolute `http(s)` / CDN `publicPath` is not supported.

Third-party script hosts are allowed through `extraSources['script-src']` on each policy.

#### Scenario: Relative publicPath with CSP enabled

- **WHEN** CSP is enabled and `publicPath` is a relative path
- **AND** sku streams an HTML document whose assets use that relative path
- **THEN** the CSP header allows those assets via `'self'` (and nonces/hashes as applicable)
- **AND** sku does not require an absolute/`CDN` origin allowance for sku-owned Document assets

## REMOVED Requirements

### Requirement: SSR report-to matches static Vite semantics

**Reason**: SSR `reportTo` is now a URL only, and sku names the endpoints.

**Migration**: Move the URL from `cspReportTo` to `csp.enforced.reportTo`, and from `cspReportOnlyReportTo` to `csp.reportOnly.reportTo`.
Apps that relied on Report-Only inheriting `cspReportTo` set the URL on both policies.

### Requirement: SSR ignores cspDelivery

**Reason**: SSR apps now fail validation if they set any flat CSP option, including `cspDelivery`.

**Migration**: Remove `cspDelivery`. SSR CSP is still always delivered as headers.
