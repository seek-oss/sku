# Project Configuration

## ADDED Requirements

### Requirement: No lifecycle hook at install time

The published `sku` package MUST NOT declare a `postinstall` (or any other
lifecycle script that runs at install). Installing sku MUST NOT write, modify,
or delete files in the consuming project.

#### Scenario: Installing sku produces no project files

- **GIVEN** a project with sku installed as a devDependency
- **WHEN** the package manager install completes
- **THEN** no files generated by sku (`tsconfig.json`, `eslint.config.mjs`,
  `.prettierrc`, managed `.gitignore` / `.prettierignore` blocks, `.ssl`)
  have been created or modified by the install itself

### Requirement: Configuration via commands

Sku SHALL materialise generated project configuration through the configure
path: the `sku configure` command and the configure step that runs before
other commands (`lint`, `format`, `test`, `build`, `build-ssr`, `start`,
`start-ssr`, `serve`, and the `translations` subcommands). A project
that has installed sku but not yet run any of these commands MAY lack
generated configuration files until one runs.

#### Scenario: First command configures the project

- **GIVEN** a freshly cloned sku project with no generated config files
- **WHEN** the developer runs any sku command that runs configure
- **THEN** the generated config files are written before the command performs
  its own work

#### Scenario: Explicit configure

- **GIVEN** a freshly cloned sku project with no generated config files
- **WHEN** the developer runs `sku configure`
- **THEN** the generated config files are written

### Requirement: devDependency warning on configure

When the consuming project lists `sku` in `dependencies` rather than
`devDependencies`, the configure path SHALL print a warning advising that sku
be installed as a devDependency. The warning MUST NOT fail the command.

#### Scenario: sku installed as a runtime dependency

- **GIVEN** a project whose package.json lists `sku` under `dependencies`
- **WHEN** any sku command that runs configure runs
- **THEN** a warning is printed recommending sku be moved to
  `devDependencies`
- **AND** the command proceeds

### Requirement: Postinstall skip flags removed

Sku MUST NOT read or act on the `skuSkipPostInstall` or `skuSkipPostinstall`
package.json fields. The `skuSkipConfigure` field is unaffected and continues
to gate the configure step that runs before each command.

#### Scenario: Legacy skip flag present

- **GIVEN** a project whose package.json sets `skuSkipPostInstall: true`
- **WHEN** any sku command that runs configure runs
- **THEN** the configure step runs normally
